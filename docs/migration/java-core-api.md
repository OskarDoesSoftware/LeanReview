# Java core review API

Implementation for [Port local API protection and the core review flow](https://github.com/OskarDoesSoftware/LeanReview/issues/24), following [the migration map](https://github.com/OskarDoesSoftware/LeanReview/issues/21).

This document records the #24 milestone. Subsequent credential/provider/analysis work is recorded in `java-review-analysis.md`.

## Scope

The opt-in Spring web profile serves the existing React build and implements the launch nonce/session cookie, saved-review list, create/read/refresh/history, progress, manual cohorts and layers, draft comments, and editor configuration/launch routes. It also reads the existing provider configuration so the frontend can open. Provider writes, analysis, graphs, coverage, and test execution belong to subsequent migration tickets.

The API binds to loopback even if a server-address override is supplied. API requests validate Host and Origin; mutations require the configured origin. Bootstrap is single-use and expires after five minutes. Each launch has a fresh session cookie. API responses use no-store, JSON bodies are limited to 1 MiB, and malformed or trailing JSON is rejected. Framework, SQL, and filesystem diagnostics are not returned to the browser.

Git uses argument-only subprocesses with a 30-second timeout and bounded stdout/stderr. Capture reads twice and rejects inconsistent results. Branch comparisons pin commit IDs; index and working comparisons retain their respective content and inventories. Conflicted working/index captures are rejected explicitly, including when Git's diff reports them as modified. Symlinks are represented as unavailable content and are not followed outside the repository. Text display remains capped at 2 MiB.

Git capture completes before the snapshot write transaction. Refresh checks the expected current snapshot again within that transaction. Manual state edits validate and write within one transaction. Refresh retains progress only when fingerprints, captured content, and patches agree, flags comments needing reattachment, and preserves historical snapshots. Artifact encoding and database mappings retain the existing schema and JSON format.

Editor launch substitutes file/line/column arguments directly into ProcessBuilder without a shell. It checks containment and current working text, strips a UTF-8 BOM consistently with capture, rejects oversized working text, and refuses Windows batch scripts. A before-side location opens line 1 and reports historicalLine, matching the existing API.

## Acceptance checks

Verified on Windows x64 on 2026-10-15: Maven `test` succeeds with 29 cases, 28 passed and one skipped because Windows does not grant this account symlink-creation permission. Conflict rejection assertions execute before that symlink-specific skip. Recovered unavailable-content fixtures pass the HTTP comparison. A separate Maven `verify -Dtest=CoreApiTest` also builds the executable JAR successfully. The packaged-Java Playwright flow passes, as do `npm run typecheck` and `npm run build`. The browser screenshot is saved locally as `.leanreview-test/java-core-review.png`.

The complete Java run includes 11 storage compatibility cases, four concurrent/state-edit cases, four local-access cases, three core HTTP/Git/patch cases, one HTTP restart case, one editor-launch case, one full Git capture replay, and four local Git cases. The symlink skip is within the last group. Cross-platform execution and symlink-creation evidence remain for platform acceptance.

Use JDK 25 and the Maven Wrapper as documented in `backend-java/README.md`:

```powershell
cd backend-java
.\mvnw.cmd verify
cd ..
npm run typecheck
npm run build
npx playwright test --config playwright.java.config.ts
```

The Java tests exercise real SQLite and Git repositories, loopback HTTP requests, restart persistence, simultaneous state edits and competing refreshes, and a harmless external-editor probe. They replay the frozen core HTTP responses and unauthorized-route responses. The stored v3 database names its review leanreview, while the independent HTTP oracle creates a repository named repository; the saved-list test checks the stored name directly.

`tests/fixtures/core-git.json` contains seven full saved-review comparisons generated by the existing Node implementation. The replay checks content, IDs, fingerprints, patches, artifact hashes, and pinned inventories across all/staged/unstaged/branch/unborn captures, renames/deletions, binary/oversized content, Unicode paths, CRLF, and missing final newlines. Separate patch corpora cover 106 existing-library examples plus nine focused cases. The source generator is `scripts/freeze-core-git.ts`.

The separate Playwright configuration starts the packaged Java server on port 4324 with an isolated copy of the frozen database/cache. It opens a migrated review and creates a new review through React, saves progress and a draft, changes a manual cohort name, reloads, refreshes changed content, and opens read-only history. The normal Node launcher and its data directory are not used by this test.

Runtime verification is Windows x64 only. Other platforms, complete frontend flows for analysis/graphs/coverage, default launcher changes, paired-data restore drills, and performance acceptance remain in the later migration issues. No large-repository performance improvement is claimed by this milestone.
